# 叙事工坊

面向作者主导的中篇创作工作台。人物状态、世界设定和伏笔有据可查；模型可以起草和审稿，作者决定哪些正文与变化进入正式记忆。

## 安卓版

从 [GitHub Releases](https://github.com/TheWorldFool/novel-generator/releases) 下载 `novel-generator-0.2.0-android.apk`，在安卓手机打开安装；如果系统提示，允许当前浏览器或文件管理器安装此来源的应用。安装后打开「叙事工坊」。这是直接安装的 APK，尚未上架应用商店。

- 支持 Android 7.0（API 24）及以上的 **64 位系统**，安装包包含 ARM64 手机和 x86_64 模拟器架构；不支持仅有32位系统的旧手机。请保持 Android System WebView 为较新版本。
- **手机独立运行，不用开电脑。** 手机内置 Python 创作引擎和 SQLite，复用电脑版的全书大纲、人物状态、文风分析、图片设定、审稿与确认流程。
- 无网络时可以手动编辑、保存、管理档案、预检与导出；AI 生成、文风分析和读图需要联网，并在「模型设置」填写自己的模型服务。安装包不包含大模型或 API 密钥。
- 从系统文件选择器导入参考文字或人物图片；导出 Markdown 和 JSON 时由你选择保存位置，无需授予整个相册或存储目录的访问权限。
- 安卓版在停止输入约1.8秒后自动保存正文、故事文风和大纲草稿，切后台时也会尝试保存。正在编辑的弹窗需点击其保存按钮。返回键会先关闭弹窗或保存草稿。自动保存不代表确认正文或让大纲生效。
- 模型密钥仅在本次应用进程内保留，系统回收进程或强制停止后需要重新填写。AI 生成期间请保持应用在前台；系统强制结束进程时，尚未保存的修改或尚未返回的生成结果无法保证恢复。
- 手机与电脑的作品分别保存，当前**没有自动同步，也没有 JSON 备份导入界面**。卸载应用或清除应用数据会删除手机内作品，请先导出备份。更新时使用同一来源、同一签名的 APK 覆盖安装即可保留应用数据。
- 手机上的 `127.0.0.1` 指手机本身；连接远程模型请使用该服务的 HTTPS 地址。

安卓实现和构建说明见 [android/README.md](android/README.md)。

## 启动

需要 Python 3.10 或更新版本，无需安装第三方依赖。在本目录运行：

```powershell
python app.py
```

打开 <http://127.0.0.1:8765>。Windows 也可以双击 `start.bat`，然后在浏览器打开上述地址。关闭服务终端或按 Ctrl+C 停止服务。

首次运行会创建明确的示例作品《雾港来信》，方便查看人物、伏笔和确认流程。点击左上角的「+」即可创建自己的空白作品。示例文本是内置内容，不是实时模型生成。

## 建议的写作流程

1. 在「全书大纲」粘贴自己的大纲，填写确定的结局和不可改动的约束。手动建立阶段节点，或让模型按原文拆解候选节点，检查后点击「确认大纲生效」。
2. 在「故事与文风」填写题材、读者、核心冲突和文风卡。生效大纲里的结局是写作依据，此处较早的结局设想不会覆盖它。
3. 建立人物档案，区分人物知道的事、误解、目标、关系和物品；在「世界与伏笔」记录世界事实、读者已知信息和伏笔。
4. 在创作台的「场景方案」选择本章承接的大纲节点，再填写本章意图和相关人物，手写或生成场景方案。
5. 手动写作或点击「AI 起草」，运行规则预检与 AI 审稿，再按具体意见修订。AI 审稿会将全书走向列为重点。
6. 一个阶段可以用多章推进。只有当本章真正完成当前阶段时，勾选「本章结束时完成这个阶段节点」，并从正文复制一句完成依据。
7. 核对章节摘要、候选人物变化，以及本章是否符合全书大纲；在确认窗口勾选已核对走向，再确认正文。
8. 当前阶段在已确认正文中完成后，下一章才可以绑定后续阶段。没有完成时，下一章继续承接当前阶段。

电脑版编辑后点击「保存草稿」或按 Ctrl+S。切换章节、切换页面、执行模型操作、确认和导出前会保存当前正文。关闭页面前如有未保存修改，浏览器会提示。**电脑版没有定时自动保存**；安卓版另有停止输入后的自动保存。

## 全书大纲如何约束章节

- **作者原文是方向来源。** AI 只拆解节点，不改写用户的原始大纲，不自动让候选节点生效。原文最多30000字符，最多30个阶段节点；节点可写目标、必经事件、禁止提前发生的内容及原文依据。
- **草稿与生效版本分开。** 编辑和保存大纲草稿不会改变当前写作方向。确认生效需要非空大纲、明确结局、有效节点；填写了原文依据时，引用必须与用户大纲逐字一致。
- **结构约束在请求模型之前执行。** AI 场景规划、起草和修订要求生效大纲、有效节点绑定和已确认的前文；不能跳过未完成阶段，也不能在已完成阶段后继续绑定同一阶段。
- **完整走向进入写作上下文。** 每次章节请求携带生效原文、结局、约束、所有阶段、当前阶段以及前文已经完成的节点。未来节点明确标为计划，不作为已经发生的事实或人物已知信息。
- **正文与阶段进度由作者确认。** 模型不能直接标记阶段完成。确认正文时要勾选已核对大纲；标记完成还要提供正文原句。系统校验引用存在，是否足以证明目标完成仍由作者判断。
- **修改可追溯。** 新大纲生效后，已确认章节全部进入待复核，过时的审稿结果清空。修改某章的节点归属或完成标记，也会使本章及后续已确认章节待复核。
- **历史保留。** 最近20个旧生效大纲可以恢复为草稿，重新检查并确认后才会替换当前生效方向。
- **旧作品兼容。** 升级不会擅自替用户编写大纲或修改已确认正文。未启用大纲的作品仍可手动编辑和确认，但新的 AI 章节生成必须先完成大纲设置。

阶段顺序、绑定和完成依据属于程序检查；人物行为或事件语义是否偏离大纲属于 AI 审稿与作者审核，不能保证模型永不跑偏。与全书大纲冲突时，应修改局部章节意图或明确更新大纲，而不是让模型默默更换故事方向。

## 创作参考库：文风分析与人物读图

这是保存材料、分析材料和选择采用结果的创作参考库。这里的「学习」指在请求中参考原文、提炼文风规则，不会微调模型或改变模型权重，也不是自动向量检索。

### 从参考文字提炼文风

1. 打开「创作参考库 → 文风参考」，点击「添加文字参考」。可以粘贴文字，或读取 `.txt` / `.md` 文件；单份最多30000字符。文件先尝试 UTF-8，失败后尝试 GB18030。
2. 填写学习重点，例如「只学习对白与节奏，不采用第一人称」，选择仅保存或保存并分析。
3. 模型返回视角、节奏、对白、描写、避免表达五个维度的候选规则，并附原文短引句。系统会标出未在原文找到的引句，便于人工核对。
4. 在预览中编辑并勾选想采用的维度。只有确认采用后，勾选维度才替换现有文风卡；不会改写正文。
5. 写作时可选择「只使用文风卡」或「文风卡 + 启用的原文样例」。最多同时启用3份，每份取前4000字符；分析时读取单份材料的完整原文。「故事与文风」里的手写参考片段也受这一模式控制。

原文样例仅供写作技法参考，不作为小说世界中的事实。修改参考原文或学习重点后，旧分析会清空，该份样例会停用。原先已采用的文风卡保留，需重新分析并确认才会再次改变。

### 从参考图设定人物

1. 在「人物档案」点击「从图片设定人物」，或在「创作参考库 → 人物图片」上传图片。可以选择文件、拖拽或粘贴图片。
2. 支持 PNG、JPEG、WebP，单张最多4MB；服务器检查大小及文件格式头，不信任文件扩展名。图片保存在本机数据库，作品 JSON 备份包含图片数据。单部作品最多12张人物图、40份参考材料。
3. 可以关联现有人物，说明想参考的主体、外貌、衣着或故事方向。点击「读图分析」时，图片才发送至配置的模型服务。
4. 分析结果分为「可见特征」「不确定项」「虚构人物设定建议」。外貌不代表性格、经历或真实身份；这些内容只作为明确的虚构创作建议。
5. 确认界面默认只选外貌与衣着。人物小传、目标、关系、已知信息等要分别勾选。可创建新人物或修改已有角色；未勾选的已有字段不会改变。
6. 已采用的参考图会显示在人物卡片上，可回看原图和分析。修改已有基础档案依然触发章节复核；锁定人物需要先解锁才能采用图片分析结果。

读图需要模型和服务均支持图片输入。在「模型设置」可另外填写同一服务下的「读图模型名称」，留空时使用写作模型。分析失败、返回格式错误或分析期间发生并发修改，不会覆盖已有分析及设定。

## 模型接入

在「模型设置」中填写支持 `POST /chat/completions` 的服务地址、模型名称及密钥。基础地址例如 `https://你的服务地址/v1`；也可填写完整接口 URL。本机模型可以使用 `http://127.0.0.1:端口/v1`。远程服务要求 HTTPS。

接口请求使用 `messages`、`model`、`max_tokens`、`stream: false`；响应需提供 `choices[0].message.content`。系统通过提示要求模型返回 JSON。部分模型可能不支持此协议或不能稳定返回约定结构，需自行确认服务兼容性。

图片分析采用 Chat Completions 的多模态 `content` 数组，包含文本块与 `image_url` 的 Base64 data URL；实现格式参考 [OpenAI 官方图片输入文档](https://developers.openai.com/api/docs/guides/images-vision)。其他兼容服务是否支持此格式，以其自身说明为准。

- 密钥仅存于 Python 进程内存，重启后需重新设置。也可通过 `NOVEL_API_KEY` 环境变量提供。
- 首次无已存设置时，可以通过 `NOVEL_API_BASE`、`NOVEL_MODEL` 环境变量提供默认地址和模型。
- 正文、设定等相关素材仅在点击 AI 操作时发往配置的服务；可能产生该服务的调用费用。
- 模型请求最长等待120秒；错误、格式异常或输出截断不会覆盖原稿。
- 未配置模型时，手动写作、档案管理、规则预检、状态确认、版本恢复和导出均可使用。规则预检不等于 AI 审稿。

## 正式记忆与修改规则

- 草稿与候选变化不会直接影响正式状态，模型提出的变化默认不勾选。
- 确认时需要正文、摘要，以及每个勾选变化对应的原文引句；锁定档案不接受新状态变化。
- 章节按顺序确认。修改已确认章节的正文、摘要或候选变化，会将本章与后续已确认章节标为「待复核」。这些章节的变化暂时不参与正式状态重建。
- 基础人物/世界档案代表故事开始前的设定。修改已有基础档案会使已确认章节待复核；剧情中的变化应在章节内记录。
- 单独切换档案锁定不撤销已有确认记录。基础设定与章节确认内容冲突时，作者需要逐章复核修正。
- 写第N章时只取第N章之前已确认的内容，防止使用当前章或未来章的状态。上下文含相关人物、世界规则、伏笔、前文摘要及最近两章各末尾6000字符。
- 每章保留最近100个正文版本；恢复版本会成为待确认草稿，清空可能过时的候选变化。
- 多窗口修改带有版本检查，避免旧窗口覆盖新内容。发生冲突时先复制未保存的文字，再刷新页面。

## 数据与备份

数据保存在 `data/novels.sqlite3`，该目录已加入 `.gitignore`。服务仅监听本机 `127.0.0.1`，不面向多人在线使用。

- 「导出作品」导出 Markdown 工作稿，并标明草稿、已确认和待复核章节。
- 「模型设置 → 导出作品 JSON 备份」导出当前作品的档案、章节、参考原文、分析、图片及保留的版本，文件不含 API 密钥。当前版本暂不提供 JSON 导入界面。
- 要完整恢复所有作品与模型的非秘密设置，请停止服务后复制整个 `data` 目录；恢复时同样先停止服务，再放回数据目录。
- 更换端口：`python app.py --port 8766`。使用其他数据文件：`python app.py --data D:\你的路径\novels.sqlite3`。

## 第一版边界

当前采用结构化档案、顺序摘要和近期原文构建上下文，没有向量检索、知识图谱或长期自动连载。模型对人物动机与文风的判断是编辑建议，不能保证文学质量；原文依据只验证引用存在，是否真正支持状态变化仍由作者判断。所有后续章节的复核提示是保守标记，不是精确的语义依赖分析。
